วิธีทดสอบที่ใช้

Functional testing

เทียบพฤติกรรมที่เห็นกับผลที่คาดหวังของแต่ละสถานการณ์

Boundary Value Analysis

ทดสอบค่ารอบ ๆ ขอบเขต เช่น ความยาว 4/5/15/16 และ 7/8/20/21 และจำนวนสินค้า 10 ลองเพิ่มเป็น 11

Positive & negative testing

ตรวจทั้งเส้นทางที่สำเร็จ และกรณีผิดพลาด เช่น ช่องว่าง รหัสผ่านไม่ตรงกัน ความยาวไม่ถูกต้อง และชื่อผู้ใช้ซ้ำ

Evidence-based reporting

บันทึกข้อมูลทดสอบ ผลที่คาดหวัง ข้อความที่เห็นจริง และผลสรุป และเปิดข้อสงสัยไว้แทนการยืนยันเกินหลักฐาน

ทักษะที่ได้ฝึกจากโปรเจ็กต์นี้

  • เขียน test case ที่มีข้อมูลนำเข้าและผลที่คาดหวังชัดเจน
  • ใช้ boundary value กับช่องข้อความและจำนวนสินค้าในตะกร้า
  • รันเทสต์ทั้งกรณีปกติและกรณีผิดพลาด พร้อมจดข้อความที่หน้าจอแสดงจริง
  • รายงานสถานะ PASS และ Needs Investigation โดยไม่ยืนยันเกินหลักฐาน
  • เห็นคุณค่าของการทำซ้ำได้ ข้อมูลสภาพแวดล้อม และภาพหน้าจอเป็นหลักฐาน

ขอบเขตและข้อจำกัด

งานนี้ทดสอบเชิงฟังก์ชันบนเดโมที่ทำงานในเบราว์เซอร์เท่านั้น ข้อมูลอยู่ในเบราว์เซอร์ ไม่ได้เชื่อมต่อ backend จริงหรือระบบชำระเงิน และการสั่งซื้อเป็นการจำลอง ไม่ได้อ้างว่าทดสอบ production, ฐานข้อมูล, security, performance หรือหลายเบราว์เซอร์ SQL และ API ศึกษาเป็นความรู้ แต่ยังไม่ได้รันกับฐานข้อมูลหรือ API จริงในรายงานเหล่านี้
